Aide-moi à rédiger un ticket Jira (préfixe ALISE-) pour créer un test
Cypress de parcours complet : EDCE – modification de limite, en autonome.

AVANT de rédiger, analyse le repo et dis-moi ce qui existe déjà :
- Le service parcours-modification-autonome.service.ts : qu'est-ce qu'il
  fait déjà ? Est-il utilisé par une feature ?
- Les page objects existants pour les pages de modification autonome
  (cypress/support/pages/...) et leurs méthodes de vérification.
- Les features existantes sous cypress/e2e/edce/ (y compris old/).
- Les pages du parcours côté librairie
  (pages/modification/autonome/modification-limite) : liste les étapes
  dans l'ordre.
Modèle à suivre : cypress/e2e/adhesion/smoke/parcours-adhesion-carte-
autonome.feature et ParcoursAdhesionAutonomeService.

Contexte et décisions déjà prises :
- Le parcours doit tourner en intégré (integre.config.ts) et être intégré
  à une pipeline quotidienne via un tag (@smoke + un tag de parcours).
- Happy path uniquement en intégré. Les cas d'erreur technique (CSM en
  échec) relèvent des tests mockés (WireMock).
- Chaque page doit être vérifiée avant de passer à la suivante (contenu
  clé, pas seulement l'URL), en réutilisant les page objects existants.
  Pas de duplication de scénarios.
- Si une page d'erreur (page-erreur-*) s'affiche, le test doit échouer
  avec un message explicite indiquant l'étape, pour distinguer une
  régression d'un problème d'environnement.

Format du ticket :
1. Énoncé : En tant que…, je veux…, afin de…
2. Spécifications fonctionnelles :
   - Contexte
   - But
   - Détail : étapes du parcours, vérifications par page, données de
     test nécessaires, tags
3. Critères d'acceptation, au format Étant donné / Quand / Alors,
   vérifiables.
4. Hors périmètre.
5. À confirmer par le lead QA : environnement exact (TEST ou QA/STAGING),
   données de test, emplacement de la pipeline et filtre de tags, sort
   des tests old/.

Règles :
- Distingue clairement ce que tu as vérifié dans le code de ce que tu
  supposes. Marque les hypothèses « (à confirmer) ».
- N'invente pas de nom de fichier, de méthode ou de tag : cite seulement
  ce qui existe, ou propose un nom en le signalant comme proposition.
- Rédige en français, prêt à copier dans Jira.
